Path B — Rebuild with Aura, and the low end

Ten deterministic low-end fixtures plus the full Path B lifecycle, driven against the real app. Every fixture is synthesised by fixtures/pathb-fixtures.js from a seeded PRNG with known ground truth, so a score only moves when the engine moves.

The low end is not bass-stem extraction and nothing here scores it as if it were. What is measured is whether Aura correctly decides that a bass part exists, whether it refuses to invent one when it does not, and whether the part it writes follows the detected harmony, rhythm and section energy.

  • Presence — bass found when there is one, refused when there is not.
  • Kick confusion — a four-on-the-floor kick with no bass must not read as bass.
  • Harmony compatibility — every written note must be the detected chord root, in key.
  • Onset alignment — written steps must come from the measured low-end rhythm.
  • Section variation — sections must not all receive an identical part.
  • Range — notes must sit in a bass register, not in the singer's way.

Serve the repository root, then open /fixtures/pathb-qa.html: python3 serve.py
