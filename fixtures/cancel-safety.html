Cancellation & failure isolation

Every one of these interrupts a real import in a real running app, then asks the only question that matters: did the project change? A cancelled or failed operation may leave nothing behind — not a byte of project state, not an undo checkpoint, not a different autosave.

The comparison is JSON.stringify(serialize()) before and after, so it catches any field, not a hand-picked list. Undo depth and the autosave bytes are checked separately, because an operation could leave the project identical and still have pushed a checkpoint nobody asked for.

A periodic autosave that writes identical bytes is not a mutation, and is not counted as one. What is counted is a change in what those bytes say.
