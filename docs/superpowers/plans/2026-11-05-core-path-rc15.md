## Architecture

- **My beat** is a project whose backing is the singer's own file: `beat:{name, dur, size}` in the project state,
  the sample in the track (`mix.sample.mute=0`, `sampleIncluded`), as is (the whole file, `sampleRunsOnce`), Aura's
  patterns and song empty. "Sing over my beat" (Welcome, project menu, phone ⋯, and a fourth choice on the import card)
  picks the file and makes that project in one step; the project it replaces goes to Recents first when it holds takes
  (the share-link rule). Tempo: detected, its double, or typed.
- **The beat is not stored** (Aura's rule: imported audio is never stored, on the device or in a file). After a reload
  a my-beat project's beat lane says which file it needs and re-attaches it to the same project when given.
- **The timeline** is `max(8, song bars, beat bars, last take's bar)` wide, may pass 32 bars, and the playhead and
  readout follow it.
- **The start point**: a click (or tap) on the ruler sets the bar Play and Record start from; ■ while stopped puts it
  back at bar 1. The beat, the takes and Aura's parts start at that point; the take lands there.
- **Punch-in**: a new recording (or an imported vocal file) is appended to the track's buffer and becomes one clip at
  the start point; the track's clips under it are trimmed or split around it; the rest of the track stays. One undo
  step; the buffer only grows, so undo is clips only.
- **Hearing the other vocals while recording** (Philip, 2026-11-05, "Yes, add it to rc.15"): Record plays every
  other vocal track from the start point; the armed track's own audio after the start point stays silent (it is being
  replaced). Found in the code: `startRecording` called `start(true)` (the backing only) and takes played only
  through `playTake()`.
- Everything without a beat, a start point or a second recording renders exactly as before (`e1Saved`,
  `e2ExportGraph`, `e2ExportJitter` against f304607).

3. `cp3MyBeatTempo`: detected, double and typed tempo; the grid's bars follow.
4. `cp4WholeBeat`: the ruler reaches the beat's last bar; a take at 40 s sits at 40 s; the playhead tracks the beat.
5. `cp5StartPoint`: Play from bar N: the beat and readout start there; ■ while stopped returns to bar 1.
6. `cp6PunchIn`: a second recording at bar N keeps the first outside it; one undo puts the first back.

7. `cp7ImportTake`: a vocal file into Double lands at the start point, by the punch-in rule.
8. `cp8BeatBack`: after a reload the beat lane names the file; giving it back restores the beat to the same project.
9. The WebKit EQ (audit item 5), root-caused: **not an app defect.** The selected channel's High EQ moves the export the
   same in both engines (Bass +3 steps 1.1e-5 in both, +12 dB 3.5e-5; Warm keys +3 steps 1.1e-4 in both). The S17
   sweep moves it on Bass, where a 4 kHz shelf has almost nothing to act on, against a 1e-5 bar: WebKit's 8.74e-6 there
   is the check's setup. To fix in `n17ExportSweep` when S17 resumes (the EQ on a track with highs). No rc.15 change.
   `cp9ImportTake` took the number; `cp11LoudBeatNoClip` (found building rc.15: a loud beat plus a voice scaled the whole
   export down 4.9 dB) is the export's local limiter for a kept beat.
